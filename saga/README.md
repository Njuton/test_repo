# Раcпределенные транзакции

## Изменения в проекте

### На стороне микросервиса появился CounterController и сущность Counter

Сейчас Counter - по сути счетчик кол-ва сообщений, который пользователь прочитал / не прочитал без учёта id сообщений.

В CountControllers всего 3 метода:

- POST /counters/increment/{userId} - увеличивает кол-во непрочитанных сообщений пользователем на 1
- POST /counters/decrement/{userId}/{count} - уменьшает кол-во прочитанных сообщений пользователем на count
- GET /counters/get/{userId} - получить текущее значение счётчика

В DialogController добавлены ещё методы работы с прочитанностью сообщений:
- POST /dialog/mark-as-read для List<UUID> делает сообщения прочитанными
- POST /dialog/masr-as-unread для List<UUID> делает сообщения непрочитанными

### В Message добавлено поле read

Это булевский флаг прочитанности сообщения, который позволяет определять для сообщения, необходимо ли для него
что-то делать со счётчиком непрочитанных сообщений или нет.

### На стороне основного приложения применяется SAGA

Основная логика зафиксирована в [DialogController](../src/main/java/com/example/myapp/rest/DialogController.java)

Теперь в DialogController при отправке нового сообщения пользователю следующая логика:
- выполняется рест-запрос в микросервис для создания сообщения
- если запрос выполнился успешно, вызываем в микросервисе метод увеличения кол-ва непрочитанных сообщений для
  пользователя на 1
- если запрос на счетчик зафейлится, выполнится компенсирующая транзакция, которая откатит создание сообщения, выполнив ещё один запрос в микросервис

Также при вычитывании сообщений:
- получаем все сообщения для нужных пользователей из микросервиса (запрос_1)
- считаем кол-во сообщений, которые были прочитаны первый раз (по флагу прочитанности)
- для непрочитанных сообщений делаем их прочитанными (запрос_2)
- пытаемся уменьшить счетчик непрочитанных сообщений (запрос_3)
- для случая фэйла запрос_3, откатываем запрос_2 и возвращаем ошибку

Т.о. с использованием SAGA, счетчик прочитанных сообщений будет консистентным насколько это возможно.

## Как запустить

Подготовил `general-docker-compose.yml`, который развернёт основное приложение + БД основного приложения,
микросервис + БД для микросервиса

```shell
docker compose -f general-docker-compose.yml down
docker compose -f general-docker-compose.yml up --build
```

Доступ в Swagger-ui доступен по адресам

- основное приложение: http://localhost:8888/swagger-ui.html
- микросервис: http://localhost:8889/swagger-ui.html
